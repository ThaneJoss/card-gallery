# 卡间拾光

卡间拾光是一个独立的银行卡收藏画廊，使用原生 HTML、CSS 和 JavaScript。卡片信息在 **`cards.yaml`** 中维护，卡面原图保存在 **`assets/cards/`**。新增或更换卡面时，手动将图片保存到 `assets/cards/`，并更新 `cards.yaml` 中的路径。部署时通过 pnpm 构建，将卡面转换成 WebP，生成可以独立发布的 `public/`。

日常只需编辑中文字段，不需要写 JavaScript。将资料和卡面一起提交即可。预览和发布都使用构建后的 `public/`。

## 手动维护卡片

日常维护只需编辑 **`cards.yaml`**，把每张卡的「图片」填成可直接访问的图片 URL，或已经提交到仓库的本地相对路径。

### 新增一张卡

1. 将卡面图片保存到 `assets/cards/`，例如 `assets/cards/my-new-card.jpg`。
2. 打开 `cards.yaml`，复制下面的四行，改成自己的信息。每张卡以 `- 名称:` 开头，其他字段前面保留两个空格。
3. 将「图片」填写为对应的本地相对路径，再把 `cards.yaml` 和新增图片一起提交。可运行 `pnpm check:cards` 检查资料，再按下方构建与预览说明启动网站。

最少只需四个字段：

```yaml
- 名称: 我的新卡片
  银行: 中国银行
  类型: 信用卡
  图片: ./assets/cards/my-new-card.jpg
```

需要填写卡组织时，在后面补充：

```yaml
- 名称: 我的新卡片
  银行: 中国银行
  类型: 信用卡
  图片: ./assets/cards/my-new-card.jpg
  卡组织:
    - Visa
    - 银联
```

卡组织只有一个时，也可以直接写 `卡组织: 银联`。普通文本和图片 URL 通常不需要引号；没有大括号、结尾逗号或分号。

| 字段 | 必填 | 用途 |
| --- | --- | --- |
| 名称 | 是 | 显示的卡片名称。 |
| 银行 | 是 | 银行名称；新增银行时直接填写新名称即可。 |
| 类型 | 是 | 填写「信用卡」或「储蓄卡」。 |
| 图片 | 是 | 仓库内相对路径或 HTTP(S) 图片直链。 |
| 卡组织 | 否 | 可填 Visa、Mastercard（万事达）、银联（UnionPay）、Amex（美国运通）、JCB、Discover；一个写文本，多个写列表。 |
| 编号 | 否 | 省略时自动生成。手动填写时不能重复；复制已有记录时请修改或删除编号。 |
| bin | 否 | 卡号前 6 位或 8 位，如 `621700`；可填数字或文本。用于核实发卡行等资料，构建时保留为文本，不在页面展示。相同 BIN 可能对应多个主题或版本。 |
| 贴图四角 | 否 | 实物照片中的卡面区域，按左上、右上、右下、左下填写四个 `[x, y]`；坐标除以图片宽高，范围为 0–1。用于详情大图与三维贴图，省略时使用整张图片。更换照片后需重新标记或删除。 |

- **修改卡片**：直接修改相应字段。换图时将新卡面保存到 `assets/cards/` 并更新路径，也可填写 HTTP(S) 图片直链。
- **删除卡片**：删除从 `- 名称:` 到下一张卡之前的整段，并手动删除不再引用的原图。下一次构建会清理发布目录的旧图片。没有卡片时可以清空文件。
- **调整顺序**：银行按 `cards.yaml` 中首次出现的顺序分组。桌面四列固定为 UnionPay（银联）、Visa、Mastercard、AMEX，列标题仅在画廊顶部显示一次，缺失组织保留空位；储蓄卡在前，信用卡另起一排。同一类型、同一卡组织的多张卡按文件顺序向下排列，双标卡归入上述优先级最高的组织。JCB、Discover 和未填写组织的卡片在「其他卡组织」区域展示。筛选后仍保持固定列位。
- **银行图标**：只需填写「银行」。图标根据银行名称自动匹配，无需逐张配置；暂未收录图标的银行显示通用银行图标。银行名称与图标的对应关系统一维护在 `assets/logos/sources.json` 中。
- **图片格式与比例**：可使用浏览器支持的 WebP、PNG、JPG 等图片。列表使用 `4 : 3` 透明布局区域，卡面和大图均按原始比例完整展示，不裁切、不拉伸；原图自带留白也会保留。
- **图片直链**：填写图片本身的地址，不是图片所在的网页或网盘分享页。地址需允许无需登录即可下载；保存到本地后，部署不再依赖该来源网址。
- **本地卡面**：使用 `./assets/cards/文件名.jpg` 等相对路径。不再使用的原图需手动删除；删除前确认没有其他卡片引用同一图片。
- **格式提示**：可以用 `#` 写注释，卡片之间可留空行。缩进使用空格，不使用 Tab。文本含有 `: ` 或 ` #`，以及纯数字编号等容易被当成其他类型的值时，请用引号包住，如 `名称: "旅行卡: 蓝色"`。
- **检查资料**：运行 `pnpm check:cards`，无需下载图片即可检查格式和字段；语法错误会给出出错行列，字段错误会指出第几张卡片及中文字段名。
- **自动生成文件**：只修改 `cards.yaml`。`public/cards.js` 由构建自动生成，不手动维护；根目录的 `index.html` 是构建模板，预览请通过本地 HTTP 服务访问 `public/`。

`assets/collection.webp` 是原始素材备份，页面不再读取它，构建也不会把它复制到 `public/`。

## 构建

需要 Node.js 22 或更新版本，以及 pnpm 12.4.2（版本已写入 `package.json` 的 `packageManager`）。安装依赖后运行构建：

```sh
pnpm install --frozen-lockfile
pnpm check:cards
pnpm build
```

本地预览运行 `python3 -m http.server 8000 --bind 127.0.0.1 --directory public`，访问 `http://127.0.0.1:8000`。三维贴图需要通过 HTTP 加载，请勿直接双击 HTML 文件。

仓库统一使用 `pnpm-lock.yaml` 锁定依赖。新增依赖使用 `pnpm add`，远程构建使用 `pnpm install --frozen-lockfile`。

构建流程：

```text
cards.yaml 中的中文卡片资料和本地路径或 HTTP(S) 图片地址
  → 校验字段并生成网页需要的卡片数据
  → 读取本地卡面，或下载 HTTP(S) 图片地址对应的图片
  → 自动校正方向、等比缩小到最大宽度 1600px、转换为 WebP
  → 保存为 public/cards/1.webp 等文件
  → 生成 public/cards.js，将 image 改为 ./cards/1.webp 等站内路径
  → 打包交互脚本与共用布局逻辑为 public/app.js
  → 打包 Three.js 与三维查看器为 public/card-viewer.js，在画廊加载后的空闲时段准备
  → 发布整个 public/
```

- WebP 质量为 85；保留透明度，不放大小图、不裁切原图。参数位于 `scripts/build.mjs`。
- 每批处理最多四张图片；构建只读取卡面，不会修改 `cards.yaml`。原图需手动保存到 `assets/cards/` 并更新资料中的路径。
- `public/` 和 `node_modules/` 已在 `.gitignore` 中，不提交到仓库。`public/` 仍会占用部署平台的存储空间。
- 下载失败或内容不是有效图片时，构建报出对应卡片的 `id` 并以失败状态退出；未完成的 `public/` 会被清理。
- 已发布的网站使用自身的图片文件，浏览时不依赖原图站点；使用本地卡面时，下一次构建也无需访问原图站点。
- `pnpm test` 可验证中文资料解析、图片转换和失败处理。
- 三维查看器与 Three.js 一起打包到站内文件，浏览时无需访问 CDN；`public/card-viewer.LICENSE.txt` 随站点发布。`pnpm-workspace.yaml` 允许构建工具 esbuild 运行安装脚本。
- `pnpm test:browser` 构建后运行真实 Chromium 回归，检查加载前后大图不变、模型与大图边界对齐、点击穿透、加载中触摸接续、模型与画布复用、贴图缓存、材质、完整旋转、复位、旧纹理请求竞争和焦点恢复。首次使用需运行 `pnpm exec playwright install chromium` 安装测试浏览器；截图保存在已忽略的 `output/card-viewer/`。

## 目录

| 文件 | 用途 |
| --- | --- |
| `cards.yaml` | 手动维护的中文卡片资料及本地路径或图片网址 |
| `scripts/card-data.mjs` | 解析并校验卡片资料，生成网页需要的数据 |
| `scripts/build.mjs` | 下载、转换图片并生成发布目录 |
| `src/card-viewer.js` | 共用卡片模型、纹理替换、相机环绕、正反面材质与资源释放 |
| `src/card-texture.mjs` | 横竖纹理方向与照片四角的透视映射 |
| `src/card-presentation.mjs` | 大图和正面模型共用的尺寸、布局及照片投影 |
| `scripts/test-browser.mjs` | 三维详情的浏览器交互和画面回归 |
| `package.json`、`pnpm-lock.yaml` | 构建命令、pnpm 版本及依赖版本 |
| `public/` | 构建生成的完整静态网站，已忽略，不提交 Git |
| `assets/cards/` | 手动保存并随 Git 提交的卡面原图 |
| `app.js` | 数据校验、加载、搜索、筛选与放大查看 |
| `index.html` | 网站名称、页面文案、首页链接与页面结构 |
| `styles.css` | 颜色、字体、间距、银行卡比例与响应式布局 |
| `assets/card-mark.svg` | 卡间拾光独立品牌标识及 favicon |
| `assets/logos/` | 银行及卡组织品牌图标 |
| `assets/logos/sources.json` | 银行名称与图标对应关系，以及银行和卡组织图标来源 |
| `assets/collection.webp` | 旧图集备份，不参与页面加载 |
| `.nojekyll` | 让 GitHub Pages 直接发布静态文件 |

## 视觉与品牌

- 采用与 webapps 一致的冷灰、白色和蓝色视觉风格。首页使用无衬线站名，以蓝色强调“拾光”，点击可返回本站 `./index.html`；保留“叠卡拾光”矢量 favicon。
- 标题、正文和控件统一使用 Inter 与系统无衬线字体回退，不加载在线字体或新的 UI 库。
- 冷灰页面 `#f6f7f9`、白色控件和详情面板 `#ffffff`、深蓝灰文字 `#182230`、辅助文字 `#526075`、蓝色强调 `#2563eb`；选中状态采用浅蓝 `#eff4ff` 配深蓝文字 `#1d4ed8`，边框为 `#e2e6ec`。颜色、字体、间距与动效变量集中在 `styles.css` 的 `:root` 中。
- 内容最大宽度为 1480px，标题、工具栏、结果说明、画廊和页脚共用对齐线。1920×1080 浏览器默认四列；1024px 及以上保持四个卡组织固定列位，600–1023px 两列、小于 600px 单列；窄屏隐藏空占位以便阅读。银行板块使用交替淡色背景，悬停或键盘焦点进入时通过边框和柔和阴影突出当前银行，不移动布局。
- 收藏条目采用开放式排版：完整卡面下方展示卡名、银行、卡种和已有卡组织，长文字自然换行。卡面直接呈现在银行板块的淡色背景上，取消白色展台、外框和容器阴影，仅保留很轻的卡面阴影；控件与弹层圆角分别为 8px、16px，列表卡面为 10px，大图卡面为 16px。详情面板内使用浅灰 `#f1f3f6` 承托卡面。
- 仅在精细鼠标悬停时让卡面上移 3px，文字和展台不移动；减少动态效果偏好会关闭位移、过渡与淡入。
- 实际验收记录见 [视觉改版验收](docs/visual-redesign-checks.md)，其中 webapps 风格补充记录对应当前配色。

## 浏览功能

- 搜索银行、卡名、卡片类型及卡组织中英文名称，支持组合筛选与重置。
- 按 `/` 聚焦搜索；结果未变化时保留卡片节点。
- 银行下拉菜单按「境内银行」「香港银行」分为两栏，顶部保留「全部银行」，两栏分别滚动。香港栏收录香港中银、香港汇丰、香港众安、香港汇立、香港大象，其余银行列入境内栏；银行名称使用 `cards.yaml` 中的同名字段，新增香港银行时同步更新 `app.js` 中的 `hongKongBanks`。
- 下拉菜单显示品牌图标，支持方向键、Home、End、Enter、Esc、Tab 与点击外部关闭；银行菜单支持左右方向键切换栏目。
- 点击卡片打开详情，默认保持清晰大图。大图不可选中或拖走，鼠标和触摸事件穿透到背后的三维交互区；第一次点击、拖动或使用方向键时才显示三维效果，加载完成本身不切换画面。相机初始正对卡面，位置和尺寸与大图重合。
- 拖动让相机上下、左右完整环绕，模型和光源固定；所有银行卡复用一个模型，尺寸、圆角、厚度不随图片比例改变。按标准卡体厘米尺寸，固定约 40 厘米观看距离，并依据视口计算视场角，减小近远边缘的透视差异；旋转需要更多空间时只放宽取景，保持完整显示。
- 默认“原色”直接显示 sRGB 卡面，不叠加灯光、反射或色调映射，保持大图与三维正面的色泽一致。哑光、覆膜、虹彩为手动选择的材质效果，同时应用到正反面；背面为无文字的中性色。这些效果用于展示，不表示已采集真实卡片工艺。
- “查看另一面”环绕到相反视角；“复位”和 Home 同时恢复正面、原色与大图，新开卡片也从原色开始。聚焦卡面后可用方向键旋转；减少动态效果偏好会关闭翻面的过渡动画。
- 画廊加载后在空闲时段准备共用三维场景，加载期间的点击与拖动会保留并在模型就绪后接续，不显示等待提示；控件从打开时保留位置，避免就绪时撑高弹窗。关闭详情只隐藏模型并停止动画，保留模型、画布及最近使用的贴图；贴图缓存按约 96 MiB 的 RGBA 与 mipmap 估算预算淘汰最久未用项，当前贴图始终保留，页面退出时统一释放。快速换卡会丢弃过期结果；设备不支持三维显示或资源加载失败时仍可查看大图。
- 关闭按钮、Esc 或点击遮罩均可关闭详情，并将焦点交还给原卡片。详情面板最大宽度为 960px，与屏幕边缘至少保留 12px；内容可滚动，44px 关闭按钮保持可见，长标题完整换行。
- 适配手机、平板、桌面及减少动态效果偏好；非首行图片延迟加载。

## 发布

网站运行时不需要后端。部署平台需要执行构建，并发布 **`public/`**：

| 设置 | 值 |
| --- | --- |
| 框架 | 无 / Other / 静态网站 |
| Node.js | 22 或更新版本 |
| 包管理器 | pnpm 12.4.2 |
| 安装命令 | `pnpm install --frozen-lockfile` |
| 构建命令 | `pnpm build` |
| 发布目录 | `public` |

这样每次远程部署都会从仓库卡面生成站内图片文件。手动部署时也可先构建，再上传整个 `public/`。生成的资源使用相对路径，可部署在网站根目录或仓库子目录下。

Vercel 项目可按上表配置构建命令和发布目录。若使用 GitHub Pages，需要通过 GitHub Actions 执行构建并上传 `public/`，直接从源码分支发布不会执行图片转换。参考 [GitHub 自定义构建文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
