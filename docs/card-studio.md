# 卡面分层素材

每张卡先取得完整高清卡面，再生成去掉银行标志、文字、卡组织标志和芯片的底图。原图已足够清晰时保留原图，低清素材使用生成式重建。对比高清卡面和底图，在人工确认的元素区域内提取透明 PNG，保留每个元素在高清卡面中的位置。

生成的高清卡面与补全部分属于生成式重建。被遮挡的图案由模型推测；低清原图中的小字、号码和图形细节可能被改写。透明图层的 RGB 来自完整高清卡面，alpha 由局部差分与区域、颜色约束估计，边缘可能残留背景。它们适合卡面设计与三维展示，不是银行提供的原始设计文件；重叠回底图也不保证逐像素复原高清卡面。具体制作方式记录在每张卡的 `notes` 中。

## 网页使用

- **高清卡面**：默认三维纹理，直接拖动即可环绕观察。
- **纯底图**：显示已经移除文字与标志的图案。
- **分层展示**：底图与透明元素分别渲染；分离距离为零时元素回到卡面，增大距离后可从侧面观察。可单独显示或隐藏图层。
- **原始卡面**：保留仓库原图，实物照片仍使用 `cards.yaml` 中的「贴图四角」。矫正后的高清与底图不再应用这组照片坐标。

在图层列表或位置图中选择元素后，可查看透明预览、像素位置和尺寸；预览可切换深浅棋盘格，方便查看白色文字或深色笔画。三维视图也可开启「深色背景」，便于观察已经分离的白色元素。PNG 是元素的局部裁切，下载的 JSON 同时提供归一化与像素坐标。前后按钮按当前筛选结果浏览；关闭详情后焦点回到当前卡片。

## 目录与坐标

素材目录以 `cards.yaml` 的编号命名：

```text
assets/card-studio/<cardId>/
  index.json
  hd.webp
  clean.webp
  layers/
    bank-logo.png
    bank-name.png
    ...
  prompts.md
```

`index.json` 示例：

```json
{
  "version": 1,
  "cardId": "example-card",
  "status": "ready",
  "width": 1600,
  "height": 1000,
  "hd": "hd.webp",
  "clean": "clean.webp",
  "elements": [
    {
      "id": "bank-logo",
      "label": "银行标志",
      "kind": "logo",
      "image": "layers/bank-logo.png",
      "box": [0.1, 0.2, 0.15, 0.12]
    }
  ],
  "notes": ["高清卡面与底图经过生成式重建。"]
}
```

`box` 为 `[x, y, width, height]`，以正向高清卡面左上角为原点，横向除以整图宽度、纵向除以整图高度。上面的元素对应 `[160, 200, 240, 120]` 像素；PNG 为 `240 × 120`，在整图的 `(160, 200)` 放置。竖卡仍以其正向图片左上角计量，无需自行旋转坐标。

`kind` 支持 `logo`、`text`、`chip` 和 `other`。`text` 可选，仅在确认内容时填写。图片路径均相对于本张卡的素材目录。

高清卡面与底图必须有相同尺寸；图层必须是含可见内容及透明区域的 PNG，裁切尺寸须与坐标吻合。构建会检查这些条件，错误会定位到卡片或元素。新素材的图片全部完成后再写入 `index.json`。

已观察到的芯片、徽标透明孔及金葵花白字问题使用 [透明图层回修](../assets/card-studio/_processing/refinement.md) 中的脚本处理，并保存初始 alpha 供复修。

尚未制作的卡片不需要这个目录，继续显示原始卡面。原素材本身是占位图时明确记录状态：

```json
{
  "version": 1,
  "cardId": "example-card",
  "status": "placeholder",
  "notes": ["现有素材为占位图，待补充真实卡面。"]
}
```

## 发布与校验

运行 `pnpm build`，已完成的素材会发布至 `public/studio/<cardId>/`。构建生成最长边不超过 640px 的列表缩略图，避免画廊批量加载所有高清图；打开详情后才按选择加载三维纹理。多个卡面视图共享画布、模型及纹理缓存。

下载的 `index.json` 保留相对图片路径，增加 `coordinateOrigin: "top-left"` 及每个元素的 `pixels` 数组。将 PNG 与 JSON 按目录一起保存即可在其他设计工具中还原位置。提示词记录与制作说明留在源码素材目录，不随站点发布；概要记录不等同于完整生成请求。

运行 `pnpm test` 检查资料与发布流程，运行 `pnpm test:browser` 检查桌面、手机、图层显隐、下载和加载竞争。构建不会修改原卡面或 `cards.yaml`。
