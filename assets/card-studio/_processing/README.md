# 卡面图层处理记录

已制作分层素材的真实卡面均经过逐张视觉定位：已有锦绣山河样例复用；其余调用内置图像工具生成高清与去字底图。众安原图本来已达高清，模型首版引入白色斜纹而弃用，最终完整高清保留原图。中信马年卡只有占位素材，未编造真实图像。农行只此青绿卡直接使用图库原图，未制作分层素材；已移除被替换社保卡的分层与处理记录。

`regions/*.json` 保存逐元素归一化区域、类别、深浅色笔画约束和相交区域排除规则。坐标以各卡 `index.json` 中完整高清图片的宽高为基准。`provenance.json` 是初次生成输出的来源记录，运行不依赖其中的绝对路径。

从仓库根目录可重新提取单张卡：

```sh
node assets/card-studio/_processing/extract-layers.mjs ccb-long-card-debit
node assets/card-studio/_processing/refine-layers.mjs
```

重新提取会覆盖该卡的透明 PNG，并清除对应的旧 alpha 基线，让后续回修采用新提取结果；请先保存需要保留的人工修订。脚本只读仓库内的 `hd.webp` 与 `clean.webp`，不会重写高清图、底图或索引。初次抠图使用模型输出 PNG，而保存版为高质量 WebP，因此重新提取像素可能有轻微压缩差异。初次三个样例另有人工颜色/几何约束，已转成配置模式；实底徽标和芯片的最终透明度修复由 `refine-layers.mjs` 完成。

## 处理边界

- 内置工具负责生成式高清重建与去字补图；Node + sharp 只做对齐、局部差分和透明层导出。
- PNG 的 RGB 来自完整高清卡面，alpha 来自局部差分、人工区域与颜色约束。它不是模型原生分层，也不保证原始设计像素保真。
- 同色底牌中的字母、芯片金属面不能仅依靠差分：最终修复要保留整个实底轮廓内部。
- 极小原图中的姓名、号码、细字和纹理可能被模型重建；不可据此核实实际发卡信息。
- `prompts.md` 标为概要的内容不是逐字调用日志；列出的约束及额外修补可指导后续编辑，但不能保证精确复现。
- 透明层应放到深浅棋盘格检查，尤其注意浅底白字、同色底牌、图层交叉区域和文字边缘。
