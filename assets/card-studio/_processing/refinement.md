# 透明图层回修

`refine-layers.mjs` 在首轮区域提取后处理已经观察到的问题：芯片与实底徽标内部出现透明孔、相邻图案混入，以及白色标志和文字过淡。它只调整 alpha，保留 PNG 原有 RGB、尺寸及 `index.json` 中的坐标。

在项目根目录运行：

```sh
node assets/card-studio/_processing/refine-layers.mjs
```

也可在命令末尾指定一个或多个卡片编号。尚未完成的素材和占位项会跳过。

芯片与银联实底徽标的文字、金属接触面可能与背后的卡面同色，单纯差分会误将这些像素抠除。脚本从初始 alpha 的主要连通区域估计凸轮廓，并填充内部透明孔；蓝底 Amex 徽标同样处理。独立的 AMERICAN EXPRESS 文字不填成矩形。轮廓是基于现有分割的近似，处理后需在棋盘格上查看形状和边缘。

金葵花卡的四个白色文字或行标区域采用局部亮度与低色差约束，保留白色主体和过渡边缘。该规则仅用于这张已检查过的浅灰金属卡，不自动套用到其他浅色底图。

汇立卡的白色行标和行名在差分后出现颗粒状半透明，使用三个颜色通道均接近白色的条件补强主体；原有边缘 alpha 保留。

广发 Lucky 卡的芯片先通过低色差约束排除相邻的粉色笔画，再填充金属主体。浙商卡的银联徽标用白色外框确定轮廓，排除去字前后发生变化的背景红色圆弧。这两条约束只应用于对应卡片的指定图层。

每个处理过的元素，其初始 alpha 保存在 `alpha/<cardId>/<elementId>.png`。重复执行使用这份基线，避免轮廓随着处理次数扩大。`extract-layers.mjs` 重新提取时会自动移除对应旧基线；若用其他方式重新生成某一 PNG，应先移除该元素对应的 alpha 基线，再运行脚本并重新目检。

这些处理改善透明图层的独立使用效果，不证明生成的文字、细节或补全背景与原始设计一致。素材的生成式重建说明仍适用。
